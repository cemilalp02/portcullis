Open-source scanner for AI agent context files

Checks what your coding agent will read and run, before it does.

Opening a repository with Claude Code, Copilot, Cursor or Gemini CLI hands part of the agent's authority to whoever wrote it. Portcullis reads the agent's instruction files, hooks, tasks, MCP servers and the scripts they run, and reports hidden instructions, commands that run without asking and invisible text. It runs locally, sends nothing anywhere and never executes what it scans.

01

Install

Release binaries for Linux, macOS and Windows on amd64 and arm64 are on the releases page. Every archive carries SLSA build provenance and the checksums are signed with Sigstore, so you can check that a download was built by this repository before you run it:

gh attestation verify portcullis_0.1.0_linux_amd64.tar.gz --repo cemilalp02/portcullis

Or build it with Go 1.26.9 or newer:

go install github.com/cemilalp02/portcullis/cmd/portcullis@latest
Everyday use
portcullis scan path/to/repoCheck a cloned repository before opening it with an agent.
portcullis scan --html report.html .Also write a self-contained HTML report.
portcullis lockApprove the current agent files; verify fails if any of them changes without a new approval.
portcullis baselineAccept existing findings so only new ones are reported.
02

What it reads

Only the files an agent loads by itself or that run without asking, in three families. A file is never executed and never sent anywhere.

Instructions
CLAUDE.md AGENTS.md GEMINI.md SKILL.md and everything next to it, Claude commands and sub-agents, Cursor, Windsurf and Cline rules, Copilot instructions, prompts, agents and chat modes, Gemini CLI commands
Configuration that runs commands
Claude Code and Gemini CLI settings and hooks, VS Code tasks and workspace settings, dev containers (including initializeCommand, which runs on your machine), npm install scripts, MCP server definitions
Scripts those commands run
A hook that calls bash .claude/hooks/start.sh is only as safe as start.sh: the scripts named by hooks, tasks and lifecycle commands are read and checked too

What it finds

MCPServers launched through a shell, unpinned packages, plain HTTP, literal secrets
SkillsNetwork use the description does not mention, unrestricted allowed-tools: Bash, sudo

Portcullis matches patterns and structure. A malicious instruction in plain, polite language without known markers can get past it; it reduces risk, it does not remove it. The threat model lists these limits.

04

In pull requests

The GitHub Action downloads the release binary and runs it only after verifying its provenance and checksum. Findings appear on the diff, in the Security tab and in the job summary, with the HTML report kept as an artifact.

The configuration, baseline and lock are read from the base commit, so a pull request cannot weaken the check that reviews it.

CI guide

      - uses: actions/checkout@v7
      - uses: cemilalp02/portcullis@v0.1.0
