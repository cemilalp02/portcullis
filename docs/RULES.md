## PCL-AEX-001

**Claude Code hook**

- Severity: `info` · Confidence: `high` · Since: `2026.10.0`
- Targets: config · OWASP: ASI05

Claude Code runs this command automatically on the given event. Hooks are legitimate, but a hook committed to a repository runs on every developer's machine that opens it with Claude Code.

**Fix:** Review the command before trusting the repository.

## PCL-AEX-002

**VS Code task runs when the folder is opened**

- Severity: `low` · Confidence: `high` · Since: `2026.10.0`
- Targets: config · OWASP: ASI05

The task has runOptions.runOn set to folderOpen, so VS Code (and compatible editors) start it as soon as the folder is opened in a trusted workspace.

**Fix:** Remove runOn: folderOpen or review the command before trusting the folder.

## PCL-AEX-003

**Dev container command runs on the host**

- Severity: `medium` · Confidence: `high` · Since: `2026.10.0`
- Targets: config · OWASP: ASI05

initializeCommand runs on the developer's machine, not inside the container, before the container is created. It is the dev container field with the widest access.

**Fix:** Move the command into the container (onCreateCommand, postCreateCommand) or review it carefully.

## PCL-AEX-004

**Auto-executed command runs a local script**

- Severity: `medium` · Confidence: `low` · Since: `2026.10.0`
- Targets: config · OWASP: ASI05

A hook (Claude Code or Gemini CLI), folder-open task or dev container command runs a script from the repository. Portcullis analyses the command, not the script, so the script needs a human review.

**Fix:** Review the script, or inline a short, reviewable command.

## PCL-AEX-005

**Inline interpreter code in an auto-executed command**

- Severity: `medium` · Confidence: `low` · Since: `2026.10.0`
- Targets: config · OWASP: ASI05

An automatically executed command passes program code inline (node -e, python -c, powershell -Command). Inline code is hard to review and a common way to hide payloads.

**Fix:** Move the code into a reviewed script file or remove it.

## PCL-AEX-006

**All project MCP servers enabled without approval**

- Severity: `high` · Confidence: `high` · Since: `2026.10.0`
- Targets: claude-settings · OWASP: ASI04, MCP03

enableAllProjectMcpServers makes Claude Code start every server in the repository's .mcp.json without asking, so a malicious server definition runs as soon as the project is opened.

**Fix:** Remove the setting and approve MCP servers individually.

## PCL-AEX-007

**Permission prompts disabled in Claude settings**

- Severity: `high` · Confidence: `high` · Since: `2026.10.0`
- Targets: claude-settings · OWASP: ASI02

The repository's Claude Code settings set the default permission mode to bypassPermissions, so every tool call - including ones triggered by injected instructions - runs without asking.

**Fix:** Remove the setting; keep the default permission mode.

## PCL-AEX-008

**Unrestricted shell access pre-approved**

- Severity: `high` · Confidence: `medium` · Since: `2026.10.0`
- Targets: claude-settings · OWASP: ASI02

The settings pre-approve every shell command (Bash or Bash(*)), so the agent can run anything without asking.

**Fix:** Allow only the specific commands the project needs, e.g. Bash(npm test).

## PCL-AEX-009

**npm install-time script**

- Severity: `info` · Confidence: `high` · Since: `2026.10.0`
- Targets: config · OWASP: ASI04

npm runs this script automatically during npm install / npm ci, including when an agent installs dependencies.

**Fix:** Review the script; consider --ignore-scripts for untrusted packages.

## PCL-AEX-010

**Claude settings redirect API traffic or inject code through the environment**

- Severity: `high` · Confidence: `high` · Since: `2026.10.1`
- Targets: claude-settings · OWASP: ASI03, ASI04

The project's Claude settings set an environment variable that sends the agent's API requests, and with them the API key, to another host (ANTHROPIC_BASE_URL, a proxy), or that loads code into every process the agent starts (NODE_OPTIONS, LD_PRELOAD). It takes effect as soon as the repository is opened.

**Fix:** Remove the variable from the project settings. Endpoint, proxy and CA settings belong in managed or user settings, not in a repository.

## PCL-AEX-011

**Gemini CLI hook or tool command**

- Severity: `info` · Confidence: `high` · Since: `2026.10.2`
- Targets: gemini-settings · OWASP: ASI05

Gemini CLI runs this command on its own: a hook on one of its events, or the tool discovery command (at start-up) and tool call command (whenever a discovered tool is used) from .gemini/settings.json. A command committed to a repository runs on every machine that opens it with Gemini CLI.

**Fix:** Review the command before trusting the repository.

## PCL-AEX-012

**VS Code agent tools approved without asking**

- Severity: `high` · Confidence: `high` · Since: `2026.10.2`
- Targets: vscode-settings · OWASP: ASI02

The workspace settings turn on global auto-approval of chat tools (chat.tools.autoApprove or chat.tools.global.autoApprove), so the agent runs every tool, including terminal commands and file edits, without asking. Writing this setting was how a prompt injection turned Copilot into remote code execution (CVE-2025-53773).

**Fix:** Remove the setting from the repository; approve tools in the chat as they are used.

- Reference: <https://code.visualstudio.com/docs/copilot/chat/chat-tools>

## PCL-AEX-013

**VS Code terminal commands approved by a catch-all rule**

- Severity: `high` · Confidence: `high` · Since: `2026.10.2`
- Targets: vscode-settings · OWASP: ASI02

chat.tools.terminal.autoApprove approves terminal commands the agent runs without asking. A rule whose pattern matches every command line (/.*/, /.+/, /^/) approves all of them, so an injected instruction can run anything in the terminal.

**Fix:** Approve only specific, harmless commands, e.g. {"npm test": true}.

- Reference: <https://code.visualstudio.com/docs/copilot/chat/chat-tools>

## PCL-AEX-014

**VS Code automatic tasks allowed without asking**

- Severity: `medium` · Confidence: `high` · Since: `2026.10.2`
- Targets: vscode-settings · OWASP: ASI05

task.allowAutomaticTasks set to "on" lets tasks with runOn: folderOpen start as soon as the folder is opened, without the prompt VS Code shows by default.

**Fix:** Remove the setting; let each developer allow automatic tasks for themselves.

## PCL-AUT-001

**Instruction override**

- Severity: `high` · Confidence: `medium` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI01

The text tells the model to ignore or replace the instructions it was given. This is the classic prompt-injection opener; in a repository file it is read by every agent that opens the project.

**Fix:** Remove the text. If the file documents prompt injection, phrase it as an example (the rule skips lines that clearly discuss attacks).

## PCL-AUT-002

**Hiding actions from the user**

- Severity: `high` · Confidence: `medium` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI01, ASI09

The text asks the agent to keep something from the user or to act silently. Legitimate project instructions want the user informed; concealment is a strong sign of a hijacked agent.

**Fix:** Remove the instruction and review what the agent was supposed to hide.

## PCL-AUT-003

**Fake chat-role or system markers**

- Severity: `medium` · Confidence: `medium` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI01

Chat-template tokens and role tags (<|im_start|>system, <system>, [INST]) try to make repository text look like a system or developer message so the model gives it higher authority.

**Fix:** Remove the markers; repository files cannot carry system instructions.

## PCL-AUT-004

**Jailbreak or unrestricted-mode claim**

- Severity: `medium` · Confidence: `medium` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI01

The text claims the model is in a special mode without its usual rules (developer mode, DAN, jailbroken). Such text exists only to talk a model out of its safeguards.

**Fix:** Remove the text.

## PCL-AUT-005

**Flags that disable agent permission checks**

- Severity: `high` · Confidence: `high` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI02

The file starts an agent, or tells the agent to start another one, with flags or modes that run every tool without asking (--dangerously-skip-permissions, --yolo, bypassPermissions). Any injected instruction then executes unchecked. Documentation that merely lists these flags is not reported.

**Fix:** Remove the flag; grant narrow permissions instead.

## PCL-AUT-006

**Instruction to skip permission prompts**

- Severity: `medium` · Confidence: `medium` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI02

The text tells the agent to approve tool calls on its own or not to ask the user before acting. Combined with any injected instruction, this removes the human from the loop.

**Fix:** Remove the instruction or limit it to specific, harmless commands.

## PCL-AUT-007

**Instruction to install persistence**

- Severity: `medium` · Confidence: `medium` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI05

The text asks the agent to add SSH authorized keys, scheduled tasks, git hooks or start-up entries. These are classic persistence locations that survive the agent session.

**Fix:** Remove the instruction and check those locations on any machine where an agent followed it.

## PCL-AUT-008

**Instruction to change shell start-up files**

- Severity: `medium` · Confidence: `low` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI05

The text asks for changes to shell start-up files such as ~/.bashrc or ~/.zshrc. Setup guides do this for PATH or environment variables, but it is also a simple way to run code in every future shell.

**Fix:** Check what is added; prefer project-local environment files.

## PCL-AUT-009

**Instruction to send secrets elsewhere**

- Severity: `high` · Confidence: `medium` · Since: `2026.10.1`
- Targets: instruction, config, script · OWASP: ASI01, ASI03

The text asks the agent to send credentials, keys or environment files to a URL, a webhook or an e-mail address. An agent following it hands the attacker whatever secrets the session can read.

**Fix:** Remove the instruction, treat the repository as hostile and rotate any secret an agent may already have sent.

## PCL-AUT-010

**Instruction to follow encoded content**

- Severity: `high` · Confidence: `medium` · Since: `2026.10.1`
- Targets: instruction, config, script · OWASP: ASI01

The text tells the agent to decode a blob (base64, hex, ROT13) and do what it says. Encoding hides the real instruction from people and from text scanners; the agent decodes and obeys it anyway.

**Fix:** Decode the content yourself, review what it asks for and remove it.

## PCL-AUT-011

**Instruction to plant code in generated files**

- Severity: `high` · Confidence: `medium` · Since: `2026.10.1`
- Targets: instruction, config, script · OWASP: ASI01, ASI05

The text tells the agent to add a download-and-run step, an eval of encoded data or a child process to every file of some kind it writes. The repository then backdoors the code the agent produces for its users, long after the instruction file was read.

**Fix:** Remove the instruction and review code the agent already generated in this repository.

## PCL-AUT-012

**Persistence that downloads or runs remote code**

- Severity: `high` · Confidence: `high` · Since: `2026.10.1`
- Targets: instruction, config, script · OWASP: ASI05

A persistence location (crontab, shell start-up file, SSH authorized_keys, git hooks, launch agents, Windows Run keys) is combined on the same line with a download, a decoded payload or a network shell. That is a foothold that keeps fetching attacker code after the agent session ends.

**Fix:** Remove the instruction or command and inspect that location on every machine where an agent may have followed it.

## PCL-ENG-001

**Target file too large to analyse**

- Severity: `high` · Confidence: `high` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI04

An agent context file is larger than the analysis limit. Padding a file with megabytes of filler is a known way to push a payload past scanners, so the file is reported instead of being skipped silently.

**Fix:** Inspect the file manually. Legitimate instruction and configuration files are small; raise --max-file-size only after review.

## PCL-ENG-002

**Configuration file could not be parsed**

- Severity: `medium` · Confidence: `medium` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI04

A configuration file that can execute commands is not valid JSON with comments. Tools differ in how they recover from errors, so a broken file can still be executed by one tool while hiding its content from another. Strict consumers (npm, Claude Code) refuse such a file, so most broken files execute nothing; editors that recover from errors (VS Code tasks, dev containers) are the remaining risk.

**Fix:** Fix the syntax error and re-run Portcullis. Text rules were still applied to the file.

## PCL-ENG-003

**Duplicate key in configuration**

- Severity: `high` · Confidence: `high` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI04

The same key appears twice in one JSON object. Parsers disagree on which value wins, which lets an attacker show reviewers one value while a tool uses the other (parser differential).

**Fix:** Remove the duplicate key and review which value is intended.

## PCL-ENG-004

**Unusual text encoding**

- Severity: `medium` · Confidence: `medium` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI06

Agent context files are normally UTF-8. UTF-16 or invalid byte sequences can hide text from byte-level tools while an agent may still decode it.

**Fix:** Convert the file to UTF-8 and review its content.

## PCL-ENG-005

**Link to an agent context file points outside the repository**

- Severity: `high` · Confidence: `high` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI04

A symbolic link or junction with the name of an agent context file resolves outside the scanned directory. An agent reading it may load files from elsewhere on the machine, such as credentials, into its context.

**Fix:** Replace the link with a regular file inside the repository.

## PCL-ENG-006

**File could not be read**

- Severity: `high` · Confidence: `high` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI04

An agent context file could not be read, so it was not analysed. The scan result is incomplete and Portcullis exits with code 2.

**Fix:** Fix the file permissions or remove the file, then scan again.

## PCL-ENG-007

**Portcullis configuration inside the scanned tree is ignored**

- Severity: `info` · Confidence: `high` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI04

The repository contains a Portcullis configuration or baseline file. In untrusted mode such files are ignored, because a malicious repository must not be able to configure or silence its own scanner.

**Fix:** Nothing to do when scanning third-party code. Use --trusted only for your own repositories.

## PCL-ENG-008

**Agent context files inside skipped directories**

- Severity: `info` · Confidence: `medium` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI04

Directories such as node_modules or vendor are skipped, but they contain agent context files (for example skills or MCP configurations shipped by packages). Those files were not analysed.

**Fix:** Scan the dependency directory separately if agents in this project read it.

## PCL-ENG-009

**Change touches Portcullis configuration**

- Severity: `medium` · Confidence: `high` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI04

The change under review adds, modifies or removes Portcullis configuration, the baseline, context.lock or custom rules. In pull-request mode Portcullis keeps using the versions from the base commit, so the change cannot weaken its own review, but reviewers should check what it re-approves or suppresses.

**Fix:** Review the change to this file as carefully as code; it decides what Portcullis accepts.

A single file produced more findings than the per-file limit. Remaining findings are counted but not listed, so that a hostile file cannot flood the report.

**Fix:** Fix the reported findings and scan again to see the rest.

**Fix:** Remove or repair the link.

## PCL-ENG-013

**Stale baseline entry**

## PCL-UNI-001

**Unicode Tag characters (invisible ASCII smuggling)**

- Severity: `critical` · Confidence: `high` · Since: `2026.10.0`
- Targets: instruction, config, script · OWASP: ASI06, MCP03

## PCL-UNI-009

**Word mixing Latin letters with look-alikes from another script**

- Severity: `medium` · Confidence: `medium` · Since: `2026.10.1`
- Targets: instruction, config, script · OWASP: ASI06
